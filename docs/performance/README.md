## 最新結論

- 測試資料共 5,000,101 本書，HTTP 深游標測試共 8,000 個請求，全部回傳 HTTP 200。
- 各 `afterBookId` 游標場景的 p95 為 75.05–97.69 ms，p99 為 77.88–103.23 ms，
  未隨深度線性增加。
- 99.9% 深度的 OFFSET 查詢掃描約 450 萬筆索引，單次約 1.10 秒；同位置游標查詢只讀取
  21 筆。
- 書名前綴查詢另測 300 次，HTTP 狀態全部為 200，但業務成功為 0；三個場景的 p95
  為 6.23–7.37 秒，p99 為 6.24–7.37 秒，這些數值是 `INTERNAL_ERROR` 的失敗回應延遲。
- 完整接口 SQL 會掃描約 490–499 萬筆。普通 cache-aside 冷未命中無法取得成功結果並回填，
  因此需先優化查詢或採用預熱、預計算方案，再分別測量快取命中與未命中。
- 調優後 Elasticsearch 投影在相同資料與負載腳本下完成三輪共 900 個測量請求，業務成功
  900/900；兩輪熱態 p95 為 157.67–191.63 ms，90K 前綴達 135.60–158.96 RPS。

原始資料生成與壓測腳本位於 `load-tests/`。
